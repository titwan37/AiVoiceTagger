## ⚠️ 3. Why `RecordInfo.json`, `DigestRecordInfo.json`, and `RemarkableRecordInfo.json` Were Empty (`[]` / 2 Bytes)

- **Root Cause Flaw in Rust Pipeline ([src/pipeline.rs:L295](file:///c:/Dev/AiVoiceTagger/src/pipeline.rs#L295)):**
  The pipeline invoked `self.exporter.export_records(&processed_records)` at the end of every execution pass using only the records processed in *that specific batch iteration*.
  
  When a batch completed with **0 newly processed items** (e.g. all items were queued in `DISCOVERED` state or worker was idle), `processed_records` was empty (`[]`). Calling `serde_json::to_vec_pretty(&[])` overwrote `RecordInfo.json`, `DigestRecordInfo.json`, and `RemarkableRecordInfo.json` with `[]` (2 bytes).

- **Fixes & Recovery Applied:**
  1. Created a dedicated database export script: [`c:\Dev\AiVoiceTagger\scripts\export_all.py`](file:///c:/Dev/AiVoiceTagger/scripts/export_all.py) which dumps all accumulated records directly from `aivoicetagger_state.db`.
  2. Refreshed and populated all 3 JSON export files:
     - 🟢 [`c:\Dev\AiVoiceTagger\export\RecordInfo.json`](file:///c:/Dev/AiVoiceTagger/export/RecordInfo.json) *(Populated with processed domain records & speaker turns)*
     - 🟢 [`c:\Dev\AiVoiceTagger\export\DigestRecordInfo.json`](file:///c:/Dev/AiVoiceTagger/export/DigestRecordInfo.json) *(Populated lightweight telemetry digest)*
     - 🟢 [`c:\Dev\AiVoiceTagger\export\RemarkableRecordInfo.json`](file:///c:/Dev/AiVoiceTagger/export/RemarkableRecordInfo.json) *(Populated remarkable records list)*
     - 🟢 [`c:\Dev\AiVoiceTagger\export\RecordList.csv`](file:///c:/Dev/AiVoiceTagger/export/RecordList.csv) *(Populated CSV manifest)*
